1. Vista general

Parkit conecta conductores que buscan dónde estacionar con propietarios de estacionamientos; un administrador aprueba estacionamientos y modera disputas y reseñas. Un mismo usuario puede tener los perfiles de conductor y de propietario y alternar entre ellos.

Front (Angular)Back (Express)Base (Postgres)Servicios externos

Carpetas raíz
  • Back/ — API REST: src/ (código), pruebas/ (tests node --test), src/db/schema.sql (toda la base).
  • Front/ — app Angular: src/app/ (código), vercel.json, proxy.conf.json (en local, /api → localhost:3000).
  • docs/ — deploy.md y este mapa.

2. Back por capas

Cada pedido recorre siempre las mismas capas. Para encontrar algo, seguí el endpoint de izquierda a derecha:

Las piezas que se repiten en todo el back
  • config/database.js: query(sql, params) para una consulta y withTransaction(async (client) => …) para varias juntas (todo o nada).
  • middlewares/auth.js: authenticate lee la cookie de sesión y deja req.usuario = { id, rol }; requireRole(ROLES.PROPIETARIO) corta si el perfil activo no es ese.
  • middlewares/validate.js + validators/*.js: cada validador usa campos(body).texto(...).entero(...).resultado() (de validators/helpers.js) y deja en req.body los datos ya limpios. Si hay errores responde 400.
  • utils/ApiError.js: ApiError.badRequest / unauthorized / forbidden / notFound / conflict → 400 / 401 / 403 / 404 / 409.
  • utils/asyncHandler.js: envuelve cada controller para que los errores lleguen al errorHandler.
  • utils/roles.js: estados y roles (ROLES, ESTADOS_RESERVA, ESTADOS_VIGENTES, …).

3. Front por capas

Cómo leer una pantalla
  1. Buscá la URL en app.routes.ts: te dice el componente de pages/ (y qué rol la ve).
  2. En el .ts de la página: los datos llegan con rxResource({ params, stream }) desde un service; el estado local son signal() y computed().
  3. El service (services/x.service.ts) hace this.http.get/post(...) y pasa la respuesta por aX(dto) de api.mapeo.ts.
  4. El .html usa @if, @for y los componentes de components/ui (<ui-boton>, <ui-modal>, <ui-tarjeta>…).
  5. Los errores ya llegan como Error con un mensaje mostrable (lo arma error.interceptor.ts): se muestran con error.set(e.message).

La barra lateral de cada rol se arma en layouts/layout-app/layout-app.ts ({ ruta, etiqueta, icono }).

4. Base de datos

Toda la estructura está en Back/src/db/schema.sql. Es idempotente (CREATE TABLE IF NOT EXISTS, ADD COLUMN IF NOT EXISTS, bloques DO $$ … IF NOT EXISTS): se puede correr muchas veces. Para cambiar la base se agrega al final y se corre npm run db:migrate.

Las restricciones importantes viven en la base: el EXCLUDE que impide dos reservas superpuestas en la misma cochera, los CHECK de puntajes y los UNIQUE (ej. una calificación por lado y reserva). Un error de la base se traduce a 4xx en errorHandler.js.

5. Ciclo de la reserva

  • Vencimientos a demanda: no hay reloj. Cada pedido a la API dispara revisar() si pasó un minuto (así la base puede dormir). Ver el comentario de cabecera de vencimientos.job.js.
  • Sin sobreventa: crear bloquea las cocheras candidatas con SELECT … FOR UPDATE antes de buscar solapamientos, y la base repite la garantía con un EXCLUDE.
  • Precio: utils/tarifas.js (precioDeReserva). Horario de atención: utils/horario.js.

6. Una feature de punta a punta: denuncia de reseñas

Es el mejor ejemplo para copiar porque toca todas las capas. En orden:

  1. Base: al final de schema.sql, los enums estado_denuncia_resena/motivo_denuncia_resena y las columnas denuncia_* y oculta en calificacion → npm run db:migrate.
  2. Constantes: utils/denuncias.js (MOTIVOS_DENUNCIA, ESTADOS_DENUNCIA).
  3. Validador: validators/denuncia-resena.validator.js → validarDenunciaResena (motivo obligatorio, detalle ≤500).
  4. Service: services/denuncia-resena.service.js → denunciar (transacción, FOR UPDATE, reglas de quién puede, UPDATE … RETURNING), listarDenuncias, moderar.
  5. Controller: controllers/calificacion.controller.js → denunciar (responde 201).
  6. Ruta: routes/calificacion.routes.js (POST /:id/denuncia con authenticate, requireRole, validate) y montaje en routes/index.js. Las de admin, en routes/admin.routes.js.
  7. Efecto en otras partes: reputacion.service.js excluye oculta en todos los cálculos.
  8. Tests del back: pruebas/denuncia-resena.test.mjs (helpers de pruebas/ayuda.mjs: crearUsuario, crearEstacionamiento, api(...)).
  9. Front, datos: tipos en models/calificacion.model.ts, DTO en services/api/api.dto.ts, mapeo aResenaDenunciada en api.mapeo.ts, métodos en calificacion.service.ts (denunciar) y admin.service.ts (resenas, desestimarResena, ocultarResena).
  10. Front, pantallas: modal components/reclamo/denunciar-resena, botón en pages/propietario/reputacion y pages/perfil, página pages/admin/resenas + ruta en app.routes.ts + ítem en layout-app.ts.
  11. Tests del front: api.mapeo.spec.ts, perfil.spec.ts, resenas.spec.ts.

7. Recetas para agregar cosas

A. Agregar un campo a una tabla y mostrarlo

  1. schema.sql (al final): ALTER TABLE x ADD COLUMN IF NOT EXISTS campo TIPO; → npm run db:migrate.
  2. Service del back: sumarlo al SELECT (o a la lista de columnas, ej. COLUMNAS en estacionamiento.service.js) y, si se edita, al INSERT/UPDATE (lista CAMPOS_EDITABLES).
  3. Validador: .texto('campo', body.campo, { requerido: false }) o el tipo que corresponda.
  4. Front: el DTO en api.dto.ts, el modelo en models/, el mapeo en api.mapeo.ts (campo: dto.campo) y el payload si se envía.
  5. Pantalla: mostrarlo en el .html ({{ x.campo }}) o sumarlo al formulario.
  6. Test: un caso en el .test.mjs del módulo y otro en api.mapeo.spec.ts.

B. Agregar un endpoint

  1. Service: export async function hacerAlgo(id, idUsuario, datos) con las reglas; errores con ApiError. Si toca varias tablas, withTransaction.
  2. Validador (si recibe body): export function validarAlgo(body) { return campos(body)….resultado(); }.
  3. Controller: export const hacerAlgo = asyncHandler(async (req, res) => { res.json({ x: await service.hacerAlgo(req.params.id, req.usuario.id, req.body) }); });
  4. Ruta: router.post('/:id/algo', authenticate, requireRole(ROLES.X), validate(validarAlgo), controller.hacerAlgo); (rutas fijas como /mios van antes de las que tienen /:id).
  5. Test en pruebas/: const { estado, datos } = await api('POST', '/x/1/algo', { token, body });

C. Agregar una pantalla

  1. Copiar una página parecida de pages/ (las 3 partes: .ts, .html, .css). Una lista simple: pages/admin/resenas.
  2. Ruta en app.routes.ts bajo el rol que corresponda: { path: 'algo', title: 'Parkit · Algo', loadComponent: () => import('./pages/…/algo').then((m) => m.Algo) }.
  3. Si va en el menú: un ítem en layouts/layout-app/layout-app.ts.
  4. Los datos: método en el service + rxResource en la página; error con @if (recurso.error()) antes de recurso.value().

D. Agregar una validación o regla

  • De forma (largo, tipo, rango): en el validador (validators/*.js) → 400 automático.
  • De negocio (estado, permisos, fechas): en el service, antes de escribir, con throw ApiError.conflict('mensaje') → 409. En el front se muestra sola.

E. Agregar un test

  • Back: en pruebas/x.test.mjs, test('qué pasa', async () => { … assert.equal(estado, 201); }). Helpers en pruebas/ayuda.mjs.
  • Front: x.spec.ts al lado del archivo, con describe / it / expect. Funciones puras se prueban directo; componentes con TestBed (ej. perfil.spec.ts).

8. Comandos

# Back (necesita Back/.env apuntando a la branch dev de Neon)
cd Back
npm run dev            # API en http://localhost:3000/api
npm run db:migrate     # aplica schema.sql + seed.sql (idempotente)
npm test               # todos los tests (node --test pruebas/*.test.mjs)
node --test --env-file=.env pruebas/reserva.test.mjs   # un solo archivo

# Front
cd Front
npm start              # http://localhost:4200 (proxy /api → :3000)
npx ng test --watch=false
npx ng build
  • Usuarios de prueba: los crean los tests con contraseña prueba1234 (PASSWORD en ayuda.mjs). Un admin: npm run db:crear-admin.
  • Mover una reserva en el tiempo para probar el ingreso: npm run db:mover-reserva.
  • Calificaciones de demo: npm run db:calificaciones-demo -- "Nombre del estacionamiento".
